# FAIL-02 · Kafka лежит долго: outbox растёт без предела

## Производительность прохода релея

| | 500 строк | 500 000 строк, без индекса | 500 000 строк, частичный индекс |
|---|---|---|---|
| Запрос релея | 0.17 ms | **27.5 ms**, Index Scan по pkey, Rows Removed by Filter: 500000 | **0.107 ms**, Index Scan using idx_outbox_unpublished |
| Запрос лага | 0.06 ms | **10.4 ms**, Parallel Seq Scan | **0.076 ms** |

Без индекса релей на каждом тике (2 раза в секунду) перебирал всю историю
опубликованных событий, чтобы найти новые. Частичный индекс
`ON outbox (id) WHERE published_at IS NULL` содержит только рабочую очередь,
поэтому время прохода не зависит от размера таблицы.

## Простой Kafka

|  | До | После |
|---|---|---|
| Kafka лежит 30 с | релей дёргает брокер каждые 0.5 с | задержка 1, 2, 4, 8, 16 … до 30 с |
| События после простоя | все 500 с retry_count = 5, в DLQ, **не отправятся никогда** | retry_count = 0, DLQ пуст |
| Разгребание 500 событий после подъёма | — | ~2 с |

## Найденные и исправленные баги

1. **Недоступность брокера считалась попыткой.** Через 2.5 с простоя все
   события объявлялись ядовитыми. kafka-go для пачки возвращает WriteErrors
   и при лежащем брокере, поэтому классифицируем по природе ошибки:
   попытку считаем только за постоянную (`!kafka.Error.Temporary()`).
2. **DLQ копировал, но не удалял.** Событие оставалось в outbox с
   published_at IS NULL, метрика лага росла вечно. Теперь DELETE ... RETURNING
   и INSERT в DLQ одним запросом.

## Уборка

Опубликованные события удаляются фоновой задачей раз в минуту, если старше 24 ч,
пачками по 5000. Хранение суток — для разбора инцидентов и переотправки.

## Алёрт

`prometheus-alerts.yml`: warning при лаге > 60 с дольше 2 минут,
critical при лаге > 10 минут. Подключается в prometheus.yml из OPS-14.
