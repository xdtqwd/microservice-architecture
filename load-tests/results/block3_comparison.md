# DB-07 — Сравнение до и после блока 3

## GET /orders (list)

| Метрика | До блока 3 | После блока 3 | Изменение |
|---------|------------|---------------|-----------|
| RPS | ~197 | 944 | +4.8x |
| p95 | 16.07ms | 12.33ms | -23% |
| p99 | ~30ms | ~25ms | -17% |

## Что дало наибольший выигрыш

| Правка | Эффект |
|--------|--------|
| Индекс `order_items(order_id)` | 382ms → 0.2ms на GetOrderByID |
| Keyset пагинация | 871ms → 0.08ms на последней странице |
| N+1 fix ANY(\$1) | 51 запросов → 2 на GET /orders |
| Индекс `orders(created_at)` | 231ms → 1.6ms на сортировке |

## Почему смотреть на хвосты а не на среднее

Среднее маскирует выбросы — 99 запросов по 5ms и 1 по 5000ms дают среднее ~55ms.
p95 = 5ms (всё хорошо), p99 = 5000ms (у каждого сотого пользователя тайм-аут).

Для сервисов важно p99 и max — именно там живут медленные запросы с большим OFFSET
и cache miss под нагрузкой.
